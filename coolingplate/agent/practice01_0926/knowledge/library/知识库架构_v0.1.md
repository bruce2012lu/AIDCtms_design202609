# cp-design 冷板知识库架构 v0.1

confidence: 0.8
valid_until: 2027-03-31
last_verified: 2026-10-02

本库是 `cp-design` 模块的私有一手资料库：论文、手册、标准、厂商文档、专利、数据集，以及作为 L5 登记的内部报告。它解决两件事：一是每个设计数值能指回一条外部来源的页码或表号；二是内部报告不再被当成黄金数据，而是和外部来源逐条对照。

平台层约定是外部知识统一经 `librarian` → Dify。本库不替代 Dify，它是 Dify 的上游：在本地完成下载、校验、抽取、分级和引用登记，经人工确认后再把 L1–L3 条目推给 Dify（见第 10 节）。

## 1 目录

```
knowledge/library/
  知识库架构_v0.1.md        本文件
  README.md                 入口与常用命令
  schema/entry.schema.json  条目元数据 schema（JSON Schema 2020-12）
  registry/
    entries.json            登记册（由 kb.py merge 生成，按可信度排序）
    citations.json          数值引用登记册
    benchmarks.json         验证基准清单
  files/                    原件，按类型分目录，文件名 = 条目 id
    papers/ handbooks/ standards/ vendor_docs/ patents/ datasets/
  derived/<id>/             抽取物：pages.jsonl、chunks.jsonl、tables/*.csv、figures/*.png、meta.json
  cards/<id>.md             知识卡片（公式 LaTeX、关键表、适用范围、基准数据点）
  index/kb.sqlite           FTS5 索引（可随时由 kb.py index 重建，不入库）
  reports/                  验证基准清单、内部数值对照、待用户获取、待审批依赖、建议
  tools/  kb.py  fetch.py  gci.py
  tests/  test_kb.py  test_gci.py
  _staging/<主题>/entries.json   检索子任务的待合并条目与检索日志
```

已有 `knowledge/catalog.json`、`cad-tracks.json`、`cad-kernel-gap.md` 不改。`catalog.json` 只登记项目内部文件；本库登记外部来源。两者的衔接写在 `reports/catalog_扩展建议.json`。

## 2 分类体系

| 目录 | type | id 前缀 | 收什么 |
|---|---|---|---|
| papers | paper | pap- | 期刊、会议、预印本、学位论文、国家实验室报告 |
| handbooks | handbook | hbk- | 手册、教科书、工程指南（ASHRAE Handbook、Dow 工程手册、CDA 手册） |
| standards | standard | std- | 正式标准与规范（ASME、JEDEC、OCP spec、GB/T、YD/T、ODCC、T/CIE） |
| vendor_docs | vendor_doc | ven- | 厂商 datasheet、产品指南、设计指南、白皮书 |
| patents | patent | pat- | 专利公开文本 |
| datasets | dataset | dat- | 物性表、实验数据、网页数据快照 |
| （不入 files） | internal | int- | 内部报告、算例，文件留在原处，用 `repo:` 前缀指路径 |

一条来源只属于一个 type。OCP 白皮书若不是正式 spec，归 vendor_doc 或 standard 都可以，以 trust_level 区分权威性，不靠目录区分。

## 3 命名规则

```
<前缀>-<年份>-<第一作者姓 | 机构简称 | 申请人>-<2~6 个英文短词>
```

- 全小写、连字符、ASCII。年份未知写 `0000`。例：`pap-2008-celik-gci-procedure`、`std-2009-asme-vv20`、`ven-2026-lenovo-lp2357-gb300-nvl72`、`pat-2020-jetcool-wo2020210587a1`。
- 本地文件名 = id + 扩展名，放在对应 `files/<类型>/`。同一来源的新版本用新 id（年份或版本号不同），旧条目标 `superseded`，不覆盖文件。
- 派生物目录、知识卡片都用同一个 id。这对应平台层“命名零漂移”。

## 4 元数据 schema

权威定义在 `schema/entry.schema.json`。必填：`id type title year url access trust_level stages last_verified`。

| 字段 | 含义 |
|---|---|
| authors / org / venue | 作者、机构或专利权人、期刊或标准体系 |
| identifiers | doi、arxiv、std_no、patent_no、isbn、osti_id、ntrs_id、cnki |
| url | 官方落地页。下载地址另记在 file.source_url |
| access.status | downloaded / metadata_only / pending_user / paywalled / login_required / not_found |
| access.license / redistributable / copyright_note / how_to_get | 许可与版权；能否随仓库分发；待用户获取时的合法途径 |
| file | path（相对本库或 `repo:` 前缀）、sha256、bytes、pages、source_url、downloaded_at |
| trust_level / trust_reason | 见第 5 节 |
| stages | 适用流程环节 1–9 |
| key_data[] | quantity、value、unit、condition、locator（页/表/式/图）、verified_from（fulltext / abstract / landing_page / secondary） |
| formulas[] | name、latex、validity（适用范围）、locator |
| benchmark_candidate / benchmark_note | 是否含可复现的几何 + 工况 + 实测值 |
| related_internal | 关联的内部条目 id |
| last_verified / valid_until / status / supersedes / superseded_by | 维护字段，见第 9 节 |

`verified_from` 是本库最重要的诚实性字段：只有 `fulltext` 能用作设计输入；`abstract`、`landing_page`、`secondary` 只能作线索，必须在卡片里写明“未见原文”。

## 5 可信度分级

| 级 | 含义 | 例 | 能否作验证基准 |
|---|---|---|---|
| L1 | 正式标准、权威手册、国家计量数据 | ASME V&V 20、JEDEC JESD51、NIST、ASHRAE Handbook、CDA 手册 | 能 |
| L2 | 同行评审期刊论文、经评审的会议全文 | Li & Garimella 2001、Celik 2008、Wei 2021 | 能，需写明不确定度 |
| L3 | 厂商官方技术文档、国家实验室技术报告 | Lenovo Press 产品指南、Dow 工程手册、NREL 报告 | 厂商实测数据能，宣传口径不能 |
| L4 | 专利、白皮书、预印本、营销资料 | Google Patents 文本、arXiv、OCP/ODCC 白皮书 | 不能单独作基准 |
| L5 | 内部报告、内部算例 | v2.0 / v2.1 报告、UC-01b CFD | 不能（kb.py cite 会拒绝 role=benchmark） |
| L6 | 估算、外推、口头信息 | “按流量平方外推 14–24 kPa” | 不能 |

判定规则：
1. 同一数值有多个来源时，取级别最高者为准；同级冲突时取更新、且给出测量方法与不确定度的一方，冲突本身写进卡片。
2. 级别跟着具体数值走，不跟着文档走。厂商 datasheet（L3）里的“典型值”若无测试条件，降为 L4 使用。
3. 预印本发表后升级为 L2，用新 id 或在原条目补 doi 并改级，记 `last_verified`。
4. 内部报告引用外部来源时，本库只认外部原文。内部报告转述的数字记 `verified_from=secondary`。

## 6 多模态整理

| 环节 | v0.1 实现（本机已有库） | 推荐升级（需审批，见 reports/待审批依赖清单.md） |
|---|---|---|
| PDF 文本 | PyMuPDF `page.get_text()`，逐页存 `pages.jsonl` | 扫描件 OCR：Tesseract 或 PaddleOCR |
| 切块 | 按空行分段，约 1500 字符一块、重叠 200 字符，块保留页码 | 按章节标题切分（docling / marker 能给版面结构） |
| 表格 | PyMuPDF `page.find_tables()` → `tables/pNNN_tK.csv`，`tables.json` 记页码与同页表题 | camelot / pdfplumber 处理无框线表 |
| 图片与图注 | 抽嵌入位图（≥120 px），同页 “Fig./Figure/图” 开头的文本块记为候选图注 | 曲线数字化：WebPlotDigitizer（人工）或 plotdigitizer |
| 公式 | 关键公式人工转 LaTeX，写进卡片与 `formulas[]`，标式号与页码 | pix2tex / nougat 自动识别，仍需人工复核 |
| 关键词索引 | SQLite FTS5 trigram 分词 + BM25（中英文不需分词库） | jieba 词级分词可提高中文召回 |
| 语义检索 | scikit-learn 字符 2–4 gram TF-IDF 重排（`--rerank`） | bge-m3 或 bge-small-zh 嵌入 + sqlite-vec / FAISS；或直接推 Dify |

原则：自动抽取物只是“候选”。进入卡片和 `key_data` 的数值必须由人或智能体对照原页复核，并写 locator。

## 7 引用登记册 `registry/citations.json`

工具代码与报告里每一个取自外部的数值、公式、限值，都登记一条：

```json
{"cid": "cit-0001", "entry_id": "dat-2023-nist-water-isobar-1atm", "trust_level": "L1",
 "locator": "表行 T=40.0000", "quantity": "water viscosity 40 °C", "value": "6.52729e-4",
 "unit": "Pa·s", "used_in": "design/calc/model.py:WATER_40", "role": "property", "note": "", "date": "2026-10-02"}
```

- 用 `python tools/kb.py cite ...` 写入，不手改。role ∈ value / formula / benchmark / property / limit。
- 闸门：条目必须已登记；locator 不能为空；L5/L6 条目不能以 benchmark 引用；已废弃条目不能引用。
- 代码侧约定：被引用的常量旁边写 `# kb:cit-0001`，`kb.py verify` 以后可扫描代码核对悬空引用（v0.2）。

## 8 验证基准 `registry/benchmarks.json`

每个基准一条，字段：`bid`、`title`、`stages`、`geometry`、`conditions`、`measured`（量、值、单位、不确定度）、`sources`（entry_id + locator）、`applicability_to_project`（与本项目 Re、Pr、D、H/D、S/D 的距离）、`tool_targets`（oned.py / zones.py / Fluent）、`status`（ready / needs_fulltext / needs_digitizing）。可读版本在 `reports/验证基准清单_v0.1.md`。

## 9 维护机制

- 新增：检索结果先写 `_staging/<主题>/entries.json`，`kb.py merge` 做 schema 校验后合入登记册；`kb.py ingest` 只处理 sha256 与登记一致的文件；之后 `kb.py index`。
- 更新：同 id 的元数据修订用 `merge --replace`；原件换版用新 id，旧条目 `status=superseded` + `superseded_by`。
- 废弃：`status=deprecated`，不删文件、不删条目，检索默认过滤，引用闸门拒绝。与平台 `memory_gc.py` 的“打标不删除”一致。
- 复核：`last_verified` 超过 180 天由 `kb.py verify` 报 `stale_180d`；`valid_until` 过期报 `expired`。厂商网页类（Lenovo Press、NVIDIA 文档）建议 `valid_until` 设一年内，因为页面会改版；标准按版本号管理。
- 完整性：`kb.py verify` 检查 schema、缺文件、sha256、悬空引用与悬空基准；`fetch.py --verify` 检查文件与下载日志。

## 10 候选 MCP 接口

挂在现有 `mcp/server.py` 的 `cp-design` 服务下（v0.2 实施，本版不改 server.py）。所有接口返回的正文片段都包在“以下为引用资料”边界内，作为数据，不作为指令。

| 工具 | 输入 | 输出 | 闸门 |
|---|---|---|---|
| kb.search | query, k, trust[], type[], stage, benchmark, rerank | hits[]：id、page、score、trust_level、snippet、access | 默认过滤 deprecated；结果标可信度 |
| kb.get | id | 条目、派生统计、表格清单、卡片路径、已有引用 | 无 |
| kb.cite | id, locator, quantity, value, unit, used_in, role | 引用记录 cid | 条目存在；locator 非空；L5/L6 不能作 benchmark；deprecated 拒绝 |
| kb.ingest | id 或 all, force | 每个文件的页数、块数、表数、图数 | 只收 downloaded 且 sha256 一致；需 confirm=true |
| kb.fetch | url, id, category | 下载记录（sha256） | 盗版站点黑名单；文件头校验；80 MB 上限；需 confirm=true；人工确认来源合法 |
| kb.benchmark | stage | 基准列表 | 只列 L1–L3 来源支撑的基准 |
| kb.verify | 无 | 完整性报告 | 无 |

写操作（cite、ingest、fetch）沿用现有 `cad_build` 的 `confirm=true` 约定。推送 Dify（`kb.push_dify`）不在 v0.1，等平台确认知识库归属（新建“液冷冷板库”或并入“新能源文献库”）后再加，属于平台层变更。

## 11 版权与入库策略

| 类别 | 默认 |
|---|---|
| CC-BY 开放获取论文、美国政府作品（NIST、NASA、OSTI 报告）、专利公开文本 | 可入库 |
| arXiv 预印本 | 作者版权，arXiv 非独占许可；默认不入库，只入元数据 |
| 厂商公开 PDF（NVIDIA、Lenovo、Dow、CDA 等） | 版权保留，默认不入库 |
| 付费标准、手册、期刊 | 不下载，只登记；用户合法获取后放 `files/` 并登记 sha256，默认不入库 |
| 派生物（全文文本块、表格 CSV、图片） | 与原件同等对待 |

远端仓库可见性未知，因此 `.gitignore` 建议默认忽略 `files/`、`derived/`、`index/`，只提交 schema、registry、cards、reports、tools、tests。允许入库的开放许可文件可逐个用 `!` 例外放行。详见 `reports/gitignore建议.md`。
