# 待审批依赖清单（v0.1）

日期：2026-10-02。本轮未安装任何包。v0.1 全部功能只用本机已有的 PyMuPDF 1.27、sqlite3 3.50（FTS5 trigram）、jsonschema 4.25、scikit-learn 1.8、pandas、bs4、httpx、pytest。

下表按收益排序。安装位置建议放独立 venv（如 `knowledge/library/.venv`），不要装进 `C:\veighna_studio` 系统 Python，也不要装进 `cad/.venv`（OCC 依赖敏感，见 memory/semantic/environment.md）。

| 优先级 | 包 | 用途 | 现在的替代 | 体积/风险 | 许可 |
|---|---|---|---|---|---|
| P1 | `sqlite-vec` | 在现有 kb.sqlite 里加向量表，做混合检索 | TF-IDF 字符 n-gram 重排 | 小（单个扩展），纯本地 | MIT/Apache-2.0 |
| P1 | `sentence-transformers` + 模型 `BAAI/bge-m3`（或 `bge-small-zh-v1.5`） | 中英文语义嵌入 | 同上 | 大：torch 约 2 GB，模型 0.1–2 GB；需联网下载模型 | Apache-2.0 / MIT |
| P1 | `pdfplumber` | 无框线表格提取（论文三线表很常见，PyMuPDF find_tables 对这类表召回低） | PyMuPDF find_tables | 小 | MIT |
| P2 | `camelot-py[base]` | 同上，另一套算法，适合 lattice 表 | 同上 | 中，依赖 ghostscript / opencv | MIT |
| P2 | `pix2tex`（LaTeX-OCR） | 公式截图 → LaTeX | 人工转写 | 大：torch | MIT |
| P2 | `docling` 或 `marker-pdf` | 版面分析（章节、表、公式、图注一体化），按章节切块 | 按空行切块 | 大：torch + 模型 | MIT / GPL-3.0（marker，注意传染性） |
| P3 | `jieba` | 中文词级分词，提高中文标准文本召回 | trigram | 小 | MIT |
| P3 | `rapidfuzz` | 条目去重（标题模糊匹配） | 人工 | 小 | MIT |
| P3 | `opencv-python` + `plotdigitizer` | 曲线图数字化（Nu–Re 图） | WebPlotDigitizer 人工 | 中 | Apache-2.0 / MIT |
| P3 | Tesseract（系统程序）+ `pytesseract` 或 `paddleocr` | 扫描版标准、老论文 OCR | 无 | 中到大 | Apache-2.0 |
| P3 | `CoolProp` | 水与部分二元溶液物性（含 PG 不完整的不可压缩流体库），一维工具对照 | NIST WebBook 表 | 小 | MIT |

审批建议：先批 P1 的 `pdfplumber` 与 `sqlite-vec`（无 torch，几分钟可装完）；嵌入模型是否本地跑，还是直接推 Dify 由 Dify 做嵌入，取决于平台对 Dify 知识库的安排，建议在平台层一起决定。
