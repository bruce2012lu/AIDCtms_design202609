AI 驱动算力液冷系统设计平台 · 项目规划 v1.0

文档编号 AIDC-CP-PLAT-PLAN-001 · 版本 v1.0 · 2026-10-02 · 模块 cp-design（agents/AIDCtms/coolingplate/agent/practice01_0926/）

本文件与 实施计划_v1.0.md 配套。Markdown 是唯一源文件，HTML 版由 plan/build_html.py 生成，两者内容一致。

0 结论先行

一句话：在现有 cp-design 智能体（一维脚本、参数化 CAD 内核、MCP 工具、Fluent 技能、本地设计台）的基础上，把附图的 ①–⑦ 门控流程补成 ①–⑨ 的完整链路（新增 ⑧ 数字孪生、⑨ AI 在环控制），用"单一参数源 + MCP 工具 + 技能 + 治理记忆"四件套把每一步做成 AI 可调用、人可审核、结果可复算的工作单元。

置信度：0.75。架构与选型基于仓库内已经跑通的工具链（build123d/OCP、Ansys 2026 R1 Fluent、Python 一维模型、MCP 服务），可行性较高；数字孪生与 AI 控制两段没有本地先例，置信度较低（约 0.6）。

五条核心判断

  1. 先统一设计口径，再加功能。 目前并存两套设计点：v2.0 水基线（1100 W、2.0 L/min、壳–进液 0.0326–0.0366 °C/W）和 v2.1 PG25 口径（1400 W、冷却液温升 6 °C、模组 3.512 L/min）。孔径也并存 D0.50（一维/CAD）与 D0.40（已收敛 CFD 网格）。平台第一件事是建立"设计点登记表"，让每个数字都挂在一个设计点和一个证据等级上。
  2. 一维走"自研 Python 为主、Simulink 为辅"。 已有的 design/calc/model.py、oned.py、zones.py 已经覆盖板级热阻与水力，并带 Martin 有效域、钻孔下限等规则门，应扩展成"板级热阻网络 + 托盘/CDU 水力网络"。MATLAB/Simulink（Simscape Fluids/Thermal）交给已有的 ai-matlab 智能体，负责系统级瞬态、交叉验证和 ⑧⑨ 所需的 FMU。
  3. 三维 CFD/CAE 锁定 Ansys（本机已有 2026 R1）+ PyAnsys/journal 自动化，OpenFOAM 只作备选。验证顺序必须遵守 v2.0 §10.9：先做 Re≈3000 的 Martin 锚定算例（V4），再做网格无关性，再做 1/2 整板。
  4. CAD 继续以 build123d/OCP 参数化内核为"设计真源"，SpaceClaim 负责几何清理与 CFD 流体域，SolidWorks/NX 只在需要正式工程图交付时作为出图端（视许可而定）。内核的首个升级是 pitch_x/pitch_y，否则 v2 的 216 孔几何进不了内核。
  5. AI 的价值点不在"替人拍板"，而在"把每轮迭代从几天压到几小时"：自动跑一维–CAD–网格–求解–后处理–报告，自动做规则门和偏差判读，人只在 DR 闸门做决策。所有经用户认可的做法沉淀为 skill，所有经验证的数字沉淀为带 confidence / valid_until / last_verified 的 semantic 记忆。

最需要你尽快拍板的三件事（详见 §12）：主设计点用哪套口径；Ansys 许可里有哪些模块（Fluent/Mechanical/optiSLang/Twin Builder）以及 MATLAB 是否有 Simscape；正式工程图的 CAD 平台（SolidWorks / NX / 只用开源）。

2 愿景、范围与成功判据

2.1 愿景

建成一个面向 AIDC 冷板液冷的 AI 原生设计与桌面验证平台：输入芯片热包络和系统水力边界，平台在人监督下自动完成"需求→选型→一维→CAD→CFD/CAE→工程图→试验 V&V→数字孪生→AI 控制"全链路，所有结论带证据等级和来源，可复算、可审计、可迁移到下一代芯片（Rubin 1.8–2.3 kW）。

6 各阶段 AI 与工具选型

6.1 一维设计计算（④，并服务 ⑧⑨）

方案 优点 缺点 结论
A 自研 Python 热阻 + 水力网络 已有 model.py/oned.py/zones.py 与规则门；AI 改代码快；可直接做 MCP 工具和回归测试；无许可依赖 瞬态与控制需自己写；大系统建模不如图形化直观 主线
B MATLAB Simulink + Simscape Fluids/Thermal，经 ai-matlab 智能体 系统级瞬态、泵阀管路库成熟；可导出 FMU；控制设计工具链完整 依赖许可；冷板内部射流/低 Re 关联式需自定义块；版本管理较重 辅线：托盘/CDU 瞬态、交叉验证、FMU
C Modelica（OpenModelica + ThermoSysPro/Buildings） 开源、可导出 FMU 团队无积累；液冷库需二次开发 备选（MATLAB 不可用时）
D Flownex / Ansys Twin Builder 一维 商业一维流网成熟 许可成本；与现有脚本割裂 不推荐首选

做法：把一维拆成三层——关联式库（Martin、短槽发展段、Shah–London、驻点核，含有效域）、元件库（射流阵、短槽、HBM 槽、静压仓、孔板、UQD、管段）、网络求解器（节点压力/流量 + 热阻网络，稳态用 Newton，瞬态用集总热容 ODE）。板级结果对 v2.0 回归（误差 0），托盘级再加四板并联和 Grace 支路。Simulink 模型由 ai-matlab 按同一份 DesignSpec 搭建，两边对同一工况的偏差 < 2% 才算一致。

6.2 CAD 概念设计（⑥ 前段）

方案 优点 缺点 结论
A build123d/OCP 参数化内核（现有 cad/coldplate） 已分层、已接 MCP 规则门；纯代码 AI 友好；出 STEP/DXF OCC 共面布尔段错误需过切；复杂曲面弱 设计真源
B CadQuery 与 A 同内核，社区大 与现有代码重复 不另起
C FreeCAD（Python API / TechDraw） 开源、带工程图工作台 API 不稳定、自动化脆弱 出图备选
D SolidWorks API / 宏 工程图与 GD&T 成熟；供应商通用 许可；Windows COM 自动化 正式图纸交付端（视许可）
E NX Open asm_0921 来自 NX 12；高端制造通用 许可与学习成本高 仅当客户/供应商要求
F SpaceClaim 脚本 本机已有；几何清理、流体域抽取、上色 不适合作为参数源 CFD 前处理

AI+CAD 模式：AI 不直接"画"，而是改 DesignSpec→规则门（rules.py）→内核建模→回读校核（包围盒、体积、孔数）→出预览图让人确认。首要升级：pitch_x/pitch_y、v2 规则对账表、HBM 方案 D 静压仓、水嘴/UQD 接口、asm_0921 三层板轨道参数化。

6.3 三维 CFD/CAE（⑤ 与 ⑥ 结构部分）

方案 优点 缺点 结论
A Ansys Fluent 2026 R1 + journal/PyFluent 本机已有且已跑通单胞 CHT；GPU 原生求解；转捩 SST、层流对照 整板网格 3000–8000 万，单卡显存不够需 CPU；许可并发 主线
B Ansys Icepak 电子散热前处理快 对 0.5 mm 射流常用降阶，解析驻点不足（v2.0 §10.2 已指出） 只做整机/托盘级
C Ansys Mechanical + PyMechanical 承压、压装、热应力、钎焊变形 需与 Fluent 温度场映射 结构主线
D optiSLang / Fluent ROM / Twin Builder DOE、敏感性、ROM 导出 FMU 需确认许可 ⑧ 首选（若有许可）
E OpenFOAM（chtMultiRegionFoam） 开源、可大规模并行 设置与验证成本高 备选 / 交叉验证
F ICEM（现有）/ Fluent Meshing watertight ICEM 已有六面体单胞经验；Fluent Meshing 适合整板 poly-hexcore ICEM 整板人工量大 单胞 ICEM，整板 Fluent Meshing

验证路线（不可跳步）：V1 解析算例（层流平板、圆管 f·Re）→ V4 Martin 锚定（Re≈3000 单胞，误差 < 15%）→ 单胞三套网格无关性 → 单胞转捩 SST 与层流对照 → 1/2 整板（沿 X 中线对称）→ 工况矩阵 C01–C12 → 结果回灌一维（R1）。资源上遵守 cfd-loop 的显存规则：超过 900 万单元不开 -gpu。

AI+Ansys 模式：AI 生成 journal/PyFluent 脚本副本（文件名带孔径、孔数、热流），后台提交，定时读残差与监视量，按 §10.8 判据判收敛，收敛后自动做后处理（逐孔流量、分段压降、壁温最高点、两 die 温差），报告云图走 fluent-gui-capture。

7 智能体体系设计

7.1 编排结构

平台宪法规定"限派生 ≤ 1 层，且仅 quant-research 可派生 t-*"。因此本平台不为 cp-design 派生子智能体，而采用"一个主控领域智能体 + 多技能 + 跨智能体协作"的结构：

  • cp-design（主控）：负责冷板全链路，按任务加载对应技能（相当于"角色帽"）。
  • ai-matlab（协作）：Simulink/Simscape 建模、FMU 导出、MATLAB MPC，经 orchestrator 路由或 cp-design 交接。
  • thermal-management（协作）：托盘/机柜/CDU 系统级热管理口径。
  • librarian（协作）：文献、标准、专利检索（Dify RAG）。
  • orchestrator：跨智能体任务拆解与汇总。

若后续 CFD 或控制工作量大到需要独立智能体（例如 cp-cfd、cp-twin），按平台规则作为同级领域智能体新建模块、薄加载器并在 registry.json 与 router.config.json 登记——这是平台层变更，需你确认。

继承规则沿用平台第②道闸门：只采纳 confidence ≥ 0.6、未过期、近期复核的条目；损坏或冲突条目只作线索。

平台宪法的三道闸门（技能安装、记忆继承、实盘资金动作）原样遵守。第③道针对金融，本项目不触发。另按工程风险补充以下项目级人工确认点（不修改平台宪法）：

工程闸门 触发动作

8 门控与 V&V 闭环的智能体落地

  1. 每个工具调用都返回 gate（pass / warn / block）和判据列表，沿用现有 cad_inspect 与 oned_design 的格式。
  2. 闸门评审包由 gate_review 自动生成：读取设计点表、run 目录 summary.json、记忆和开放项，按 §4.1 条件逐条打勾，并附证据链接；人只需审阅"未通过 / 待定"项。
  3. 偏差自动判读：cfd_vv 与 test_vv 按 V1–V5 阈值输出偏差表；超过阈值时自动起草 R1/R2 回路建议（杠杆排序 + 一维预筛结果），但不自动改模型。
  4. 证据等级强制：报告生成器拒绝把 E2 数字放进"整板保证值"字段；单胞热阻、单胞压降只能出现在"单胞"章节。
  5. 冲突检测：同一参数在两个锁定设计点中取值不同（如孔径 D0.50 与 D0.40）时，spec_diff 报警，要求人选定。
