AI 驱动算力液冷系统设计平台 · 实施计划 v1.0

文档编号 AIDC-CP-PLAT-IMPL-001 · 版本 v1.0 · 2026-10-02 · 配套《项目规划_v1.0》

用法：你每次下一条指令（如"执行 S0.1"），智能体只做这一步，交付后等你验收；验收通过的方法与数字再沉淀为 skill 与 memory。Markdown 是唯一源文件，HTML 版由 plan/build_html.py 生成。

0 执行规则

0.1 单步执行循环

每一步都按同一个循环走：

  1. 接指令：你说"执行 S0.1"这类步骤编号，可附带修改意见。
  2. 启动引导：智能体读 platform/CLAUDE.md、agent.md、memory/index.json 中未过期且 confidence ≥ 0.6 的 semantic，以及该步骤列出的输入。
  3. 执行：只做本步骤；产物进 runs/<时间戳>-<设计点>-<步骤>/ 或本步指定目录；不碰冻结 yaml 与已发放 STEP。
  4. 交付：给出"结论 + 证据等级 + 数字与来源 + 未冻结项 + 产物路径"，并自检验收标准。
  5. 你验收：通过 / 修改 / 否决。
  6. 沉淀：通过后写 episodic；新口径写 semantic 草案；新方法写 skill 草案。semantic 与 skill 在你确认后才定稿（见 §11）。
  7. 提交提示：关键步骤后生成 git 提交信息草案（<type>(cp-design): <summary>），真实 commit/push 由你在 GitKraken 中执行。

0.2 步骤卡字段说明

字段 含义
目标 这一步要回答的问题或交付的能力
输入 必须读取的文件、数据或前置步骤产物
AI 与工具 智能体用什么工具、技能、外部软件
交付物 文件路径与格式
验收标准 你据此判定通过；含闸门
工时 AI 执行 / 你审核（小时），求解机时另计
依赖 前置步骤
沉淀 预计产生的 skill / memory

11 Skill 与 Memory 沉淀流程

11.1 流程

  1. 步骤交付并经你验收通过。
  2. 智能体写 memory/episodic/<date>-<step>.json（自动，无需确认）。
  3. 若本步产生了新的或修正的口径、数字、环境事实，智能体起草 semantic 差异（新文件或对已有文件的修改），列出 confidence、valid_until、evidence、design_point。
  4. 若本步形成了可复用的做法（被你认可，且至少成功执行一次），智能体起草 skills/<name>/SKILL.md，状态 draft。
  5. 你确认后：semantic 写入并更新 memory/index.json；skill 状态改为 verified。被否决的草案不写入，只在 episodic 的 rejected 里留一句原因。
  6. 需要跨模块共享的 skill：复制到 platform/shared/skills/_staging/<name>/，你确认后登记 platform/shared/skills/_meta/skill-registry.json（第①道闸门）。
  7. 过期记忆不删除，由 platform/hooks/memory_gc.py 标记 expired。

  1. 用脚本从 8 份参考报告抽取所有参数表（已验证可以从 HTML 抽成文本）。

  3. 调 oned_design、hbm_design、grace_design 复算 DP-A、DP-B，与报告逐项比对。
