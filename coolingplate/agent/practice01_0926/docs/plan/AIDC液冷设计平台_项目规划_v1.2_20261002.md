与已有数字的关系：

- **流量**：
  - v2.1 的 3.512 L/min 来自 `model.py` 物性的 6 K 闭合，比推荐值 3.490 高 0.6%，在流量计精度内，可沿用为 6 K 档对照值。
  - 能量平衡流量对物性套别不敏感：各套 ρ·cp 相差 ≤ 0.8%；供液 45 °C 时相差不到 0.05%。
  - v1.1 用 ρ ≈ 1020、cp ≈ 3.9 粗估的 3.5 / 2.6 / 2.1 L/min 和 4.7 / 6.3 / 7.9 K，与本表一致到 1%，本版以本表为准。
- **物性真正影响的是 Re 与粘性压降**：相对 `model.py` 套，Re ×0.78，层流摩擦压降 ×1.28，Pr 9.92 → 12.04，射流 h 约 −2.5%；孔口等局部压降基本不变。v2.0 / `cp_b300_1d.py` 的结论“PG25 使 h 掉约 29%”基于错误物性，需在 S05 重算。
- **压降（L6 估算，以 S08、S18 为准）**：
  - v2.1 的 14–24 kPa 是把水基线 3.5–5.5 kPa 按流量平方外推到原分配表 4.0–4.2 L/min 的结果。
  - 按同一平方律粗估：3.5 L/min 约 10–18 kPa，2.6 L/min 约 6–10 kPa，2.1 L/min 约 4–6 kPa。
  - 改用推荐物性后，粘性部分再 ×1.28，6 K 档上限可能触及 20 kPa。
  - Grace 支路：0.8 L/min 时原为 22.9 kPa，摩擦部分增大；在 0.748 / 0.561 / 0.449 L/min（6 / 8 / 10 K）下约为 21 / 12 / 8 kPa。
- **含义**：放宽温升能缓解压降风险，但流量降 25–40%，Re 降到 200 左右，对流热阻上升，而热性能本来就没有余量（v2.0 DR2 有条件通过）。设计必须在 PC-1 和 PC-3 两端都校核，孔径与阵列密度由 S05 / S07 一维筛选决定（§6.11）。

### 1.5 证据等级与术语

三版证据等级合并为 E0–E5（C 版分级是 A、B 两版的超集，含义一致）：

| 等级 | 含义 | 例子 | 能写成什么 |
|---|---|---|---|
| E0 假设 / 外推 | 估值、平方律外推、占位尺寸 | PG25 整板压降 14–24 kPa（v2.1 外推）；静压箱 3–5 kPa | 只作风险提示 |
| E1 一维 | 关联式或能量平衡 | v2.0 §9 壳–进液 0.0326–0.0366 °C/W | 方案筛选、区间 |
| E2 单元胞 / 局部 CFD | 周期胞或局部带 | UC-01b m425，R(TIM–in) 0.03134 °C/W | 局部 h、孔口压降、模型标定；不外推整板 |
| E3 整板 / 半板 CFD | 含静压箱、歧管，网格无关 | 尚无 | 设计结论候选 |
| E4 样件实测 | TTV、流阻、红外、氦检，不确定度已评估 | 尚无 | 保证值依据 |
| E5 系统 SAT | 托盘 / 机柜现场 | 尚无 | 运行孪生标定 |

平台所有对外数字都要带证据等级、来源文件和日期。单元胞结果不能写成整板保证值（`agent.md` “不做”第 1 条）。

v1.2 起，每个数字同时标两个标签：

- **证据等级 E0–E5**：表示得到它的分析方式；
- **数据可信度 L1–L6**：表示来源的可靠程度。L1 标准 / 权威手册，L2 同行评审论文，L3 厂商官方文档，L4 专利 / 白皮书，L5 内部报告 / 算例，L6 估算。

**验证基准只认 L1–L3**。内部报告（L5）只用于代码改动前后的回归一致性，详见第 11 章。

### 2.4 已有结论

- 选型：分区杂交（GPU 射流 + 短槽，HBM 无喷嘴 + 限速，隔离肋）加权 4.50，排第一（v2.0 §5.1；`02_DR1_方案权衡.xlsx` 复算差约 0.05，名次不变），对齐专利方案 A。
- 水力余量大，热设计没有余量，正确方向是“用压降换换热”（v2.0 §0.1）。PG25 粘度约为水的 1.76 倍，压降余量被吃掉一部分（v2.1 §3）。
- Re_D < 2000 时不采用 Martin 1977，保证值用短槽层流 + 驻点核（v2.0 §9.4；`oned.py` 自动判定）。PG25 下 Re 更低（6 K 档 0.50 mm 孔约 400），这条纪律不变。
- 最优先的杠杆：TIM2 升级到 ≤ 0.004 °C/W，孔径 0.50 → 0.40 mm（v2.0 §9.12）。
- 单胞 CFD 的 0.0313 °C/W 比一维下限 0.0326 低约 4%（`cycle-20260926/03` 原文写“落在下限与上限之间”，与数字不符）。它是 E2，网格孔径是 D0.40，不是整板保证。
- 工艺：机加 + 真空钎焊，整板增材不作出货基线（v2.0 §6.1；专利 v1.4 §3.7）。
- 门控状态：DR0 有条件（6 项缺失输入）、DR1 完成、DR2 有条件通过（区间跨目标线；**D-001 口径下待重算**）、DR3 未完成、DR4 未开始。

### 4.4 选型对比与推荐

评分 1–5，5 最好。权重：本机可用性与许可 25%、自动化 / AI 可编程性 25%、工程可信度 20%、成本 15%、数据保密 15%（A 版权重；B、C 版权重排序结果一致）。

#### 4.4.1 一维与系统仿真（双路线）

| 方案 | 可用性 | 自动化 | 可信度 | 成本 | 保密 | 加权 | 适合做什么 |
|---|---|---|---|---|---|---|---|
| 路线 A：Python 自建（model.py + oned + zones + scipy） | 5 | 5 | 4 | 5 | 5 | **4.80** | 关联式、预算、DOE、UQ、水力网络、回归；唯一设计数值源 |
| 路线 B：MATLAB/Simulink + Simscape Fluids（经 `ai-matlab`） | 4 | 4 | 5 | 3 | 5 | **4.15** | 托盘 / CDU 系统级网络、瞬态、控制对象；与路线 A 对照 |
| Modelica（OpenModelica） | 2 | 4 | 4 | 5 | 5 | 3.80 | 开源动态系统，原生 FMU；未安装 |
| Ansys Twin Builder | 3 | 3 | 4 | 3 | 5 | 3.50 | ROM 集成、孪生部署；许可未知 |
| Flownex | 1 | 2 | 4 | 2 | 5 | 2.60 | 未装，不推荐首期 |

说明：A 版给 MATLAB 的可用性打 2 分，前提是“未探测到”。本版按 §2.5 核实结果改为 4 分（已装、许可特性在文件中，但未检出验证），加权由 3.55 升到 4.15。

推荐：**路线 A 为主**，稳态设计计算、规则判据、扫描与差距闭合全部在 Python，作为唯一数值源。**路线 B 并列**，用于托盘 / CDU 系统级、瞬态、控制对象，并对路线 A 做稳态对照：同一稳态点的 ΔTf、ΔP 偏差 < 1%，否则以 Python 为准并查 Simscape 参数。两者都只消费设计点注册表，不另存一套参数。MATLAB 许可检出失败时，路线 B 的系统模型改用 Python（scipy ODE），接口不变。

| ICEM CFD hex（replay） | 单胞、12 格带等规则几何，已有黄金 replay | 单胞与局部带继续用 |

| PyPrimeMesh | 网格脚本化 | 视许可，作为 Fluent Meshing 的脚本层 |
| gmsh / snappyHexMesh | OpenFOAM 路线 | 仅备选 |

#### 4.4.5 结构 FEA

推荐 **Ansys Mechanical（PyMechanical / PyMAPDL）**，做 3 bar 承压、300–500 N 压装、焊后热应力与平面度，可映射 Fluent 温度场；**CalculiX** 作开源备选。v2.0 §6.3 的解析板条保留为一维对照：喷嘴板跨 26 mm 时 16.73 MPa、2.65 μm。

#### 4.4.6 优化与 DOE

推荐 **Python（scipy、optuna）+ 一维模型** 做大规模筛选，覆盖 D-001 全包络；**optiSLang**（已装）在 CFD 级 DOE 和稳健性分析时使用。原则：一维筛到 3–5 个候选，再上 CFD；R1 回路的 AI 自动参数扫描与优化也走这条线（S39）。生成式拓扑流道（arXiv 2604.10941 / 2608.22787）列为 P6 之后的研究选项。

#### 4.4.7 数字孪生与控制

两条并列路线，详见第 9 章。简述：路线 A 用 Python ROM / RC 网络 → FMU，控制在 Python SIL；路线 B 用 Simscape Fluids 孪生 + MPC / RL Toolbox，在 Simulink 中做 SIL / HIL。两条路线以一维模型为共同源、FMU 为互通接口，选哪条由用户决定（Q-07）。

### 5.14 两层迭代（loop）设计

迭代分两层：

- **第 1 层：环节内循环**。在一个工作环节内部按“目标 → 执行 → 自检 → 修正”小循环跑到收敛，由 AI 自主推进。超过最大轮数仍不收敛时，按升级路径交给外循环或用户。
- **第 2 层：跨环节外循环**。即 R1–R4，携带数据回到前面的环节，多数需要用户批准。

```svg:loops
第 1 层 · 环节内循环：目标 → 执行 → 自检 →（未达判据）修正 → 执行 …；（达判据）→ 门控；（超最大轮数）→ 升级
第 2 层 · 跨环节外循环：③④ 一维 → ⑤ CFD → ⑦ 试验 → ⑧ 孪生 → ⑨ 控制；R1 ⑤→③④；R2 ⑦→③；R3 ⑧ 自标定；R4 ⑨→③
每轮循环后的累积：episodic → skill / memory 候选 → 闸门入库；知识库引用登记、缺失清单、HELP 看板
```

|---|---|---|---|---|---|

**累积**：

- **内循环每结束一轮**：AI 写 episodic 草稿（轮数、判据值、修正动作）；新出现的报错与修正生成技能修订候选。
- **外循环每结束一轮**：稳定规律、修正系数生成 semantic 候选；被推翻的旧记忆降级或标记取代（§14.1）；知识库登记新引用，并更新“缺失知识清单”与 HELP 看板（§15.4）。

所有候选都要经用户认可和闸门才能入库。

## 6 一维计算工具设计

### 6.1 定位与原则

- **唯一数值源**：设计数值只来自路线 A（`design/calc/model.py` 及其扩展）。报告、xlsx、UI、MCP 都调用它，不另抄数字（v2.0 §4.3 原则推广到全平台）。路线 B 只作对照与系统级扩展，不另存参数。
- **D-001 为默认口径**：工具缺省设计点改为 DP-P1400-6K，水 DP-A/DP-B 保留为回归用例，旧接口不带设计点时行为不变。
- **适用域门控**：每个关联式带适用域，越域时自动降级并给出警告（`oned.py` 已有 Martin 门控）。
- **证据等级标注**：输出里每个结论带 E 等级和“保证值 / 对照值”身份。
- **不改冻结件**：先用回归测试锁住 `oned.py`、`zones.py`、`model.py`，再逐步重构，重构期间旧接口保持兼容。

### 6.10 多工质改造（S41，最先做）

改造要求：

1. **快照**：改造前先对 DP-A / DP-B（水）、D0.40、Grace 两个流量点做输出快照。改造后水的结果必须逐位一致。
2. **参数化**：`fluid` 作为显式参数，取值为 `water40 | pg25_tds | pg25_guide | pg25_model(deprecated)`，物性在 T_m 由 `props` 模块按拟合式计算。缺省保持水，保证旧调用和 MCP 行为不变。
3. **防误用**：调用方传了 PG25 设计点却未传 `fluid` 时，返回 ERROR，不静默回落到水；`pg25_model` 只允许在 `--reproduce-v21` 回归模式下使用，并给 WARN。
4. **契约与测试**：工质写入输出的 `meta`。测试显式断言 `fluid`，附四件套的公式与出处（TDS 拟合式 §4.4，`kb_cite` 登记）。

### 8.4 ASME V&V 20 框架与偏差 > 15% 回路

- 对比误差 E = S − D（S 仿真值，D 试验值）；验证不确定度 u_val = √(u_num² + u_input² + u_D²)。
- u_num：三套网格，加密比 r ≥ 1.3（v2.0 要求 1 : 1.5 : 2.25），Roache GCI 折算；迭代误差为监测量 500 步漂移 < 0.5%。
- u_input：用一维网络或代理模型做灵敏度系数，再蒙特卡洛传播（TIM2 面积热阻 0.1–0.2 °C·cm²/W、功率分区、流量 ±2%、进液温度 ±0.2 K、孔径公差 +0.03/0、PG25 浓度 ±2%）。
- 判读：偏差绝对值 ≤ 15% 且 E 与 u_val 同量级时，模型可用；偏差 > 15% 触发 R2；u_val > 15% 时结论为“不可判”，先降不确定度。

```svg:vv
模型预测（1D / CFD / 孪生，带版本）→ 试验测量（TTV，带 u_D）→ 偏差 ε 与 u_val →（ε ≤ 15%）V5 通过 → DR4 闸门包
                                                                         └（ε > 15%）开 R2 工单 → 偏差分解（测量 / 装配 / 样件 / 模型）→ 反标定 → 回 ③
```

*图 8-1 · V&V 闭环（html 版为内联 SVG）。*

偏差分解顺序：先排除测量（不确定度、传感器位置、热损失），再排除装配（TIM2 厚度与压力、平面度），再排除样件（孔径一致性、钎料堵塞，用流阻曲线和 X-ray/CT 判断），最后才改模型。模型修正只改有物理意义的参数（h 倍率、TIM2 面积热阻、孔口 K、接触热阻），用最小二乘或贝叶斯反标定，并记录参数的置信区间。修正后模型升小版本号，旧版本保留，并起草 semantic 记忆候选（含适用域与 `valid_until`）。

### 8.5 试验数据格式

每次试验一个目录 `vv/tests/<日期>-<样件号>-<工况>/`：`meta.yaml`（样件号、图纸版本、台架版本、传感器与校准证书号、操作者、D-001 工况 id）、`raw.csv`（时间戳、通道、值、单位）、`steady.csv`（稳态窗口均值与标准差）、`photos/`、`ir/`。`test_import` 校验单位、量程、校准有效期、稳态判据（如 10 min 内温度漂移 < 0.1 K），不过就拒收。通道名与 §9.8 统一变量表一致。

| L4 | 专利、白皮书、预印本、营销资料 | Google Patents 文本、OCP/ODCC 白皮书、arXiv | 不能单独作基准 | 只作线索 |
| L5 | 内部报告、内部算例 | B300 v2.0 / v2.1、Grace v1.0 / v1.1、UC-01b CFD、`cycle.json` | **不能**，只作回归一致性 | 作候选，必须标 L5 |
| L6 | 估算、外推、口头信息 | v2.1“按流量平方外推 14–24 kPa”；本规划的 D-001 压降粗估 | 不能 | 只作风险提示，显式标“估算” |

两套标签同时使用、互不替代：

- **证据等级 E0–E5**（§1.5）回答“这个数是用哪种分析得到的”。
- **可信度 L1–L6** 回答“这个数的来源有多可靠”。

举例：v2.0 §9 的一维热阻是 E1 / L5，Wei 2021 的实测 Nu 是 E4 / L2。

判定规则：

1. 同一数值有多个来源时，取级别最高者。同级冲突时，取更新且给出测量方法与不确定度的一方，冲突本身写进知识卡片。
2. 级别跟着具体数值走，不跟着文档走。
3. 内部报告转述外部数字时，只认外部原文，并标 `verified_from=secondary`。
4. 只有 `verified_from=fulltext` 的数值才能作设计输入。

示例：PG25 物性。`model.py` 的 PG25_40 无出处、四个量互不自洽，按 L6 处理并停用。DOWFROST LC 25 TDS 是 L3，作设计基线；Dow 工程指南是 L3，作低粘度敏感性下限（D-003）。

### 11.2 验证分层（外部基准 + 内部回归）

| 层 | 对照对象 | 级别 | 目的 | 判据 | 未通过时 |
|---|---|---|---|---|---|
| 单元测试 | 手算点、解析解 | — | 函数与公式一一对应 | 0.1% | 修代码 |

## 12 模块化与接口契约

用户要求：每个工作环节的工具和 GUI 能独立维护、独立升级，接口相对固定，并可留冗余。

### 12.1 原则

1. **环节独立**：每个环节一个独立目录，各自有 `VERSION`、`CHANGELOG.md`、`HELP.md`、`tests/`、`TEST_REPORT.md`，可以单独发版。现有文件（`oned.py`、`zones.py`、`cad/coldplate/`）原地保留，由适配层包进模块，不搬家。
2. **只经契约交换**：环节之间只通过两类东西交换数据。一是带版本的 JSON Schema 数据契约（`AP/contracts/<name>@<major>.schema.json`，JSON Schema 2020-12）；二是标准文件（STEP AP242、FMU FMI 2.0/3.0、CSV、DXF/PDF、`.cas.h5`）。MCP 工具输入输出用同一份契约，不另定义。
3. **语义化版本**：`MAJOR.MINOR.PATCH`。小版本只增字段、不改语义、不删字段。破坏性变更必须升大版本，并且：
   - 旧大版本保留至少一个阶段的过渡期，适配层同时支持新旧；
   - 用户批准后才能发布（属工程闸门 E1 的同类动作）；
   - `CHANGELOG.md` 写明迁移办法。
4. **冗余设计**：
   - 每个契约预留 `ext`（自由扩展对象，消费方必须忽略未知键）与 `meta`（版本、生成工具、run_id、来源 `cids`、证据等级 E、可信度 L）。
   - 同一环节允许多个实现，经适配层切换并可交叉验证，例如一维的 `backend: python | simscape`，CFD 的 `solver: fluent | openfoam`，孪生 / 控制的 `route: A | B`。
   - CLI、MCP、GUI 三个入口共用同一内核函数，界面不重写判断（沿用 `软件界面方案.md`）。
5. **契约测试**：每个契约有正例和反例样本。生产方测试“输出满足契约”，消费方测试“能读上一小版本的样本”，在 CI 式脚本 `tests/test_contracts.py` 中统一跑。
6. **设计台**：采用统一外壳加各环节插件页。外壳负责导航、设计点切换、闸门看板、run 浏览、帮助；插件页只调用本环节 API，可单独升级。

### 13.1 现状（2026-10-02 读 `mcp/server.py` 核实）

8 个工具都没有输出契约版本，也没有 `units`、`warnings` 结构、出处字段。README 只列了其中 5 个。

### 13.2 设计规则

1. **命名**：MCP 线上名用 `组_动作`（下划线，满足常见客户端 `^[a-zA-Z0-9_-]{1,64}$` 的限制）。文档中的逻辑名可写作 `kb.search`，线上名为 `kb_search`。现有 8 个名字不改。
2. **契约**：输入输出都引用 §12 的契约 id 与版本，返回 §12.3 的统一包络。`tools/list` 的 `description` 写清用途、单位、适用域、闸门。
3. **四件套**：每个工具的 help 可经 `tool_help(name)` 取回，内容与 `HELP.md` 同源；公式与出处通过 `meta.cids` 追溯。
4. **安全**：
   - 只读工具默认可调；
   - 会写文件、占用求解器、花钱或动实物的工具必须 `confirm=true`，并按需走 E1–E4；
   - 缺省 `dry_run=true`，先返回计划与估算；
   - 知识库返回的正文片段包在“以下为引用资料”边界内，作为数据，不作为指令。
5. **日志**：每次调用一行 JSONL，写 `AP/runs/mcp/<YYYYMMDD>.jsonl`，字段为时间、工具、参数哈希、契约、耗时、ok/错误码、run_id。写文件类工具另在自己的 `runs/<ts>-…/manifest.json` 留痕。
6. **自测**：`server.py --self-test` 扩展为对每个工具跑契约正例和反例；新工具不过自测不注册。
7. **兼容**：三入口（CLI、MCP、设计台 HTTP）共用内核；旧参数（如 `point: "DP-A"`）保留并映射到设计点 id。

### 14.2 版本与来源追溯

### 14.3 每步强制产出与累积时机

- **每个实施步骤结束**，必须在步骤报告里给出“候选清单”（可以为空，但要写“无”）。这是步骤 DoD 的一项（实施计划 §0.4）。
