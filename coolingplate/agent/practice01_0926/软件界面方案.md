# 冷板设计台 · 软件界面方案

当前可用的是本地 HTML 设计台，不是另一套 CAD 内核。界面、记忆和几何规则读的是同一批文件。

## 现在这层

```
浏览器  →  http://127.0.0.1:8765  →  agent/practice01_0926/mcp/server.py
                                              ├─ 静态页面 agent/practice01_0926/ui
                                              ├─ cad_inspect：yaml + rules，不建模
                                              └─ cad_build：子进程调用 cad/.venv 里的 build.py
对话    →  MCP stdio 同一套工具
```

CAD 页只覆盖轨道 `parametric-v1`。另外三条轨道在页面上只作说明，避免把实测三层板或 Grace 槽写进 B300 射流参数。

人确认是界面上的勾选，对应工具参数 `confirm=true`。ERROR 时导出按钮不可用。

## 独立软件时保持的边界

若以后做成桌面程序，仍建议：

- 界面只是这个 HTTP API 的壳，规则继续放在 `cad/coldplate/rules.py`，避免界面里重写一套孔径和节距判断。
- 求解器仍走 ANSYS journal。程序负责组织目录、收集残差和打开已有 HTML 报告。
- SpaceClaim 继续 `/RunScript` 上色，不在界面里重写渲染。
- 一个设计运行一个文件夹：`agent/practice01_0926/runs/<时间戳>/` 放参数副本、日志和 STEP。冻结 yaml 只读。
- Grace 与 B300 分两个工程页，共用材料和环境记忆，不共用孔阵列参数。

桌面壳可以用 pywebview 或现有浏览器套本服务。在内核补上 `pitch_x` / `pitch_y` 之前，界面不应提供“生成 v2 整板”按钮。
